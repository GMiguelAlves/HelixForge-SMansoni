# ChIP-seq reference reuse and read preprocessing

## Reference and reusable index

The genome is SM_V10 and the annotation is the WBPS19 canonical gene set.
The uncompressed FASTA and GTF checksums are recorded in
[`reference_contract.json`](../../config/chipseq/reference_contract.json).
These checksums differ from the checksums of the compressed source artifacts;
both identify their respective byte streams, not different assemblies.

ChIP-seq uses a genomic **Bowtie2** index. An existing Salmon transcriptome
index is not a substitute: the tools use different index formats and reference
inputs. Preserve the Salmon index for RNA-seq.

The planned reusable bundle uses Bowtie2 **2.5.5**, basename `genome`, no extra
build arguments and an `alignment_index` schema **1.2** manifest generated by
the released HelixForge module. It must match the frozen FASTA, genome ID,
all six shard hashes and the Bowtie2 version used for alignment. Build and
validation status are recorded in the reference contract; availability of
this preparation does not by itself certify a bundle.

Production launches require the explicit bundle and manifest. Missing or
incompatible inputs must fail rather than silently schedule another build.
A fresh validation-only execution must confirm reuse without a construction
task. Per-run validation still checks the index, independently of `-resume`.
Private filesystem locations belong in site configuration, not this repository.

## Registered trimming policy

[`trimming_policy.json`](../../config/chipseq/trimming_policy.json) is the
prospective ChIP-seq preprocessing policy, not a claim to reproduce each
publication's original preprocessing.

| Setting | Choice |
|---|---|
| Tool | Trim Galore 0.6.10 with Cutadapt 5.1 |
| Quality | Explicit Phred cutoff 20; expected Phred+33 encoding |
| Minimum retained length | 25 bp |
| Adapter | Tool auto-detection per library; retain detection report |
| PE reads | Keep complete pairs only; both mates must pass the length cutoff |
| Fixed cropping, orphan rescue, poly-A trimming | Not requested |
| Application | IPs, inputs and other registered controls, in SE or PE mode |

Q20 is the documented Trim Galore quality cutoff, explicitly selected for this
analysis. The 25 bp floor limits very short retained reads without cropping
all reads to one length. It does **not** guarantee unique genomic mapping;
the separate MAPQ and BAM policies remain unchanged. No RNA-seq configuration
is consulted for these choices.

Adapter auto-detection is not proof of library chemistry. Inspect its report,
especially an inconclusive call or a fallback choice. PRJNA1090249 was generated
by ChIPmentation, so inspect the expected Nextera/tagmentation signal; do not
force a single sequence onto IPs and inputs solely from their instrument model.

The same registered policy applies to shared controls and to both narrow/broad
invocations. Do not choose different thresholds to improve a peak count, FRiP
or apparent reproducibility. Preserve raw and post-trim FastQC, MultiQC,
trimming reports, retained reads/bases and length distributions before accepting
the analysis. Wrong encoding, substantial unexplained loss or residual adapter
signal requires review, not an automatic parameter change.

### Two-colour sequencing caveat

NextSeq/NovaSeq-type poly-G artifacts are not equivalent to ordinary
low-quality tails. Trim Galore offers a distinct `--nextseq` mode that is
mutually exclusive with `--quality`; the current native HelixForge trimming
contract does not expose that option. Therefore Q20 must not be described as
poly-G correction. Inspect raw/post-trim QC for these libraries, including the
NextSeq 550 data in PRJNA1090249. If residual artifacts require this processing,
hold acceptance and specify/test an explicit extension rather than injecting
unsupported flags or silently preprocessing outside the pipeline.
